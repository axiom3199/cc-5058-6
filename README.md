# 虚拟考察队层级任务运行时（HTN Runtime）

把「布置观测点」「路线踏勘」这类高层任务，按**方法（Method）规则**真实分解搜索为
搬运、定位、组装、安装、供电、标定、检查等**可执行原语动作**，由虚拟角色在三维场景中执行。
任务分解与动作执行严格分离；父任务必须在底层动作全部结束且**世界条件谓词成立**时才算成功。

## 图形入口（主要使用方式）

```bash
node scripts/serve.mjs        # 或 npm run serve
```

然后用浏览器打开：

**http://localhost:8080/**

页面为三栏布局：

- 左栏：任务条件与异常注入按钮、**方法适用性核对（任务来源）**、**分解搜索优化指标面板**。
- 中栏：三维场景（Three.js / WebGL），可观察角色移动、搬运、组装与设备占用；鼠标可旋转缩放。
- 右栏：可展开的**分解树**（每个复合节点可展开查看「高层任务 → 方法适用性核对 → 选中方案」
  的来源，以及每个叶子的能力需求、显式依赖、占用资源）、世界条件结果区
  （built / mounted / powered / calibrated / verified 谓词与世界事实）、事件日志与异常横幅。

顶部控件：场景选择、恢复策略选择（局部换人 / 祖先回退）、**分解搜索优化模式**、
分解、单步推进、自动推进、重置，以及条件更改按钮：
**令队员退出、航测仪损坏、补送电源箱、按当前世界状态重新分解**。

「分解搜索优化」下拉框由同一个规划内核驱动，三档可选：

- `proof`（默认）：**带证明的子计划复用**，命中需重放前提观察并确认方法仍是当前首选。
- `nogood`：仅缓存**失败前提**及其 TTL，成功分解不缓存。
- `off`：不缓存、逐方法完整展开，作为对照基线。

切换模式会丢弃旧缓存并按新模式重新分解；左侧优化指标面板实时显示内核统计
（完整展开数、证明命中/拒绝、失败前提命中、撤回、换人、世界失效次数与席位/器材预订台账），
所有数字都来自真实 `plan()` 返回的 `stats` 与预订台账，界面不自行估算。

> 注意：分解树的书写/层级顺序**不是**执行顺序。调度只看叶子上显式声明的 `dependsOn` 依赖
> 与资源锁（作业台、航测仪），满足条件的并行叶子会同时执行。

## 六个预置场景

| ID | 场景 | 核对要点 |
| --- | --- | --- |
| `standard` | S1 标准编队·部件齐全 | 四人全编制，标准方法分解并由世界条件确认建成观测站 |
| `lightTeam` | S2 精简编队·缺部件 | 标准方法因缺观测仪/电源箱与能力不足被**排除**，自动选中轻量化方法 |
| `missingPower` | S3 缺电源箱·动态切换 | 先按可行方案分解；界面补送电源箱后**重新分解搜索**为标准方法 |
| `withdraw` | S4 队员途中退出 | 主工程师搬运途中退出，演示两种恢复办法（见下） |
| `sharedDevice` | S5 两任务共享航测仪 | 布置与踏勘争用同一台航测仪 → 资源串行化；注入损坏后先失败方**级联阻止**下游 |
| `noSubstitute` | S6 无替补能力 | 唯一工程师退出，局部换人会破坏后段电气/标定能力 → **自动升级为祖先方法回退** |

## 两种队员退出恢复办法

在界面「恢复策略」下拉框中选择，或 CLI 传 `--recovery=`：

1. **替换退出队员的子任务（substitute）**
   - 仅在 travel / carry **途中**退出时触发替换语义；替补必须能接下退出者在该任务内
     **全部未完成动作**的能力（保护后段能力条件，不只看当前一个叶子）。
   - 整棵树内属于退出者的未完成叶子统一改派，并自动插入一个「汇合移动」合成叶子，
     带屏障依赖，避免替补先走远而无法接手物资。
2. **回溯到上层重新分工（rollback）**
   - 丢弃未完成叶子（已完成的世界变更保留），对最顶层复合任务按**当前世界状态**重新跑分解搜索，
     原先可行的方案会因队员退出/部件缺失而不再适用，从而选出新方案。
   - 局部换人找不到满足全部后段能力的替补时，运行时**自动升级**为祖先回退（见 S6）。

## 失败级联与资源冲突

- 叶子动作有启动前提 `pre()` 与结束一致性校验 `verifyEnd()`；前提不符即失败。
- 任一叶子失败后，运行时沿依赖边求传递闭包，把所有不再适用的下游叶子标记为「已阻止」，
   不会再启动（多路径依赖图用工作队列处理，不会重复或死循环）。
- 作业台 `benchA`、航测仪 `drone1` 是受限资源：同一时刻只允许一个叶子占用，第二个争用动作等待，
   实现并行任务间的串行化。

## 完成条件（不靠状态名称报成功）

复合节点关闭时要求：直接叶子全部进入终态 **且** `goal(state, ctx)` 世界谓词为真。
例如观测站要求 `built && mounted && powered && calibrated` 且存在 `verified:<siteId>` 事实；
动作全做完但世界条件不满足时父任务判失败。

## 分解搜索优化（proof / nogood / off）

优化只改“怎么搜索分解”，不改“什么是合法分解”。三种模式产出的计划骨架都必须落在
穷举 oracle 的合法集合内，专项测试据此核对**漏掉的合法分解数量为 0**。

### 计算顺序（为什么复用是安全的）

1. **算复用键**（`memo.makeKey`）：键 = 任务名 + 稳定序列化的任务上下文 +
   当前在岗队员“实际具备的能力签名”（按队员 id 排序，含身份，避免同名装备/同能力混淆）。
   换人、能力增减、上下文变化都会改键。
2. **失败前提短路**（nogood）：同世界版本且未超 TTL 才命中，直接返回失败；
   世界事实变化（版本号变）或超时即作废，重新展开。
3. **带证明查找**（proof）：同版本直接信任证明快照；版本变化时**不把未观察到的条件当作确定**——
   逐条重放证明里记录的前提观察（仅记录方法真正读过的谓词），并重新跑一遍方法适用性核对，
   只有“缓存方法仍是当前首选方法”时才复用，否则作废回完整展开。
4. **物化再核对**：命中后深拷贝缓存模板、重分配 uid，并对每个叶子确认旧队员仍在岗且具备
   该叶子“实际消耗的能力”；不满足则换人。
5. **预订冲突处理**：物化时若车辆席位/器材借用已被占用，**撤回该缓存分支的全部临时预订**
   （分支作用域），放弃缓存退回完整展开。
6. **落地提交**：仅顶层复合成功时把分支预订提升为 root（跨后续任务保持占用）；
   嵌套子复合不单独提交，随外层方法同生共死，失败一次整体撤回。

### 两级预订与“谁上车、谁持借器材”

`src/ledger.mjs` 的预订台账分两级作用域：

- **branch（分支，可回滚）**：某次方法尝试的临时席位/器材借用，方法失败或缓存物化冲突时整体撤回。
- **root（已提交）**：顶层方法落地后的预订，对后续团队视为“已占用”容量。

车辆容量为 2（两人共乘一辆），同一队员在任意车上至多占一个席位；器材按设备 id 借用，
同分支内可复用。基准报告会直接打印每个席位的上车名单与每件器材的持有者终态。

### 及时失效与不伪报

- 世界状态带单调递增的 `revision`；事实/人员/物资/设备/载具变更经 `state.touch()` 推进版本。
- 运行时每个 tick 动作改变世界后也 `touch()`；祖先回退重分解前显式 `memo.invalidate()`。
- 未知观察类型一律保守作废；规划失败如实返回 `ok:false`，基准与界面都不会把失败报成成功。

### 基准与专项测试

```bash
npm run bench          # 三模式对照：展开数、命中、撤回、换人、可执行性、谁上车/持借
npm run bench:check    # 与 bench/baseline.json 的结构性指标比对（不含计时，避免机器波动伪报）
npm run bench:save     # 重新保存结构性基线（仅在行为确有预期变更时使用）
npm run test:opt       # 优化专项：证明复用、TTL、世界失效、席位撤回、同名装备互换零漏分解
```

`bench/` 内置六类负载：席位冲突（容量满→冲突留痕/撤回/换人/如实部分失败）、同名装备互换、
世界事实变化、失败前提 TTL、重复子任务负载、嵌套复合子树复用。每个用例都用
`enumeratePlans` 穷举合法计划作 oracle，再用“去成员化骨架”比较，确认缓存模式零漏报；
产出的计划还会被实际执行到世界谓词 goal 成立，把展开数/可执行计划映射到执行证据。

## 命令行（仅辅助）

```bash
node cli/run.mjs <场景ID> [--recovery=substitute|rollback] [--break-drone=<tick>]
node cli/run.mjs --help          # 列出场景 ID
npm test                         # 引擎自检 + 界面联动 + 优化专项（全部断言）
node scripts/dom-check.mjs       # 无浏览器时的界面控制器联动验证（DOM/three 桩）
npm run bench:check              # 优化基准结构性基线比对
```

CLI 会打印方法适用性核对记录、选用方案、逐 tick 事件、叶子终态、世界条件与任务结论。

## 代码结构

- `src/state.mjs`：世界状态（地点、队员、物资、设备、观测站、事实谓词、日志）。
- `src/actions.mjs`：原语动作定义（能力需求、时长、前提、进入、结束、结束校验、资源声明）。
- `src/methods.mjs`：复合任务与方法注册表、适用性谓词、分解构造（含嵌套复合任务）。
- `src/planner.mjs`：递归分解搜索、方法适用性追踪、按能力负载均衡的队员分派、三模式缓存复用、穷举 oracle。
- `src/memo.mjs`：能力签名、复用键、前提观察记录/重放、proof 与 nogood（TTL）缓存及统计。
- `src/ledger.mjs`：车辆席位/器材借用的两级（branch/root）预订台账、分支提交与撤回、占用审计。
- `src/runtime.mjs`：依赖/资源调度、动作执行与世界确认、两种恢复策略、失败级联。
- `src/scenarios.mjs`：六个预置场景与角色能力表。
- `bench/`：分解搜索优化基准域、六类负载用例、三模式对照运行器、结构性基线与专项测试。
- `web/`：图形界面（`index.html` 入口、`app.mjs` 控制器、`scene3d.mjs` 三维场景、本地 vendored three.js）。
- `cli/`：无头运行器、打印入口与自检。

## 验证说明与环境限制

- `npm test` 串联三套断言，当前全部通过：
  - 引擎自检（`cli/selftest.mjs`）：方案适用性排除、动态补件重分解、局部换人、强制祖先回退、
    共享设备串行化与故障级联阻止、世界条件确认。
  - 界面联动（`scripts/dom-check.mjs`）：真实 `web/app.mjs` 在最小 DOM/three 桩下驱动控件，
    含优化模式切换、指标面板由内核 `stats` 渲染、补送电源后重新分解切换方案。
  - 优化专项（`bench/test-opt.mjs`）：证明复用、nogood TTL、世界变化失效、席位冲突撤回/换人、
    同名装备互换与全用例相对穷举 oracle 的**零漏分解**、缓存计划可执行到 goal。
- 若某项优化导致“展开数/可执行计划”之外的行为退化（漏合法分解、计划不可执行、世界条件误判），
  专项测试与 `bench:check` 会非零退出；此时应回退该优化而非放宽断言，基准永不伪报。
- 本容器缺少 Chromium 运行所需系统库（如 `libnspr4`）且无 root 权限安装，
  因此 **WebGL 画面未能在容器内做真实浏览器目视验证**；`scripts/browser-check.mjs` 保留供有浏览器的环境运行。
  三维场景的渲染逻辑与引擎联动已通过桩验证，实际画面请在本地浏览器打开图形入口查看。
